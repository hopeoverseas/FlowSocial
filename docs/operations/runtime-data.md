# 运行数据维护

## 备份

在 `apps/flowsocial` 下运行：

```powershell
npm.cmd run backup:database
```

默认备份进入 `data/backups/`。建议保留最新备份和重大迁移前的命名里程碑备份。

## 清理边界

可直接清理：日志、可重新生成的 artifacts、过期滚动备份。

必须先迁移引用：知识文件、活动数据库、发布记录关联的内容产物。

数据库或 WAL 正在被服务占用时，不执行文件级删除、改名或复制；先停止服务并确认 4273 端口已经释放。

## 接手时的私有数据迁移

公开源码只交接新建的 `defaults/store.json` 空种子，整个本机 `data/`（含原 seed）均不提交。初始化顺序为独立数据目录 seed、原本机 seed、公共空种子；已有 SQLite 状态不会被重新初始化，兼容说明见[公开空种子](../../apps/flowsocial/docs/migrations/public-empty-seed.md)。仅复制代码不能恢复历史内容。
需要迁移时，由原负责人通过私有渠道提供数据，密钥另行配置；禁止提交到 GitHub，即使仓库为私有。

1. 记录当前源码提交、Node 版本和账号/策略/内容精确版本，停止写入并使用备份命令取得一致性备份。
2. 停止服务后，配套保存知识文件、数据库引用的图片及本地内容产物，保留相对路径与哈希。
   涉及 `data/knowledge-files/`、`data/xhs-integrated-page-assets/`、`data/wechat-preupload-artifacts/`、
   `data/wechat-generated-raster-assets/`、`artifacts/` 等；以实际数据库引用为准，不假设这些目录足够覆盖所有外置文件。
3. 在新目录先用同版代码和复制的数据验证，重新配置 Provider 与平台授权。若使用 `FLOWSOCIAL_DATA_DIR`，
   设为绝对路径；它控制业务数据库和部分资产目录，不会自动搬迁全部 artifacts 或本地配置。
4. 核对账号、活动策略、待审版本、图片可读性、发布记录与指标归属。发现旧机器绝对路径时先修复引用，
   不删除缺失记录，也不原地改写历史快照。
5. 验证通过后再切换日常工作；保留原机器只读备份。失败时回到原代码及原配套数据，禁止把旧数据库覆盖到运行中的新实例。

代码包本身不改变 schema、合同、开关或业务状态，无数据迁移要求。后续功能改动应按对应迁移记录执行；
不能仅回退代码就假定数据库与历史产物也已回退。
