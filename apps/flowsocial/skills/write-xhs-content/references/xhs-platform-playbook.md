# 小红书图文生成规则

## 1. 内容任务

把一条笔记当作三个相互协作的界面：

- 标题与封面负责说明“这条内容能帮我什么”；
- 卡片负责用滑动节奏交付核心价值；
- 发布正文负责补充语境、解释和互动，不照抄全部卡片。

三者必须兑现同一个 `content_promise`，但不能逐字重复。

## 2. 标题与封面

- 使用明确对象、场景、问题或结果，不使用空泛“必看、绝了、震惊”。
- 标题只承诺正文和卡片实际覆盖的内容。
- 封面 headline 保持单一信息焦点，副文案只补对象、条件或范围。
- 没有证据时不使用“最好、第一、100%、一定”等绝对表述。

## 3. 发布正文

- 开头在前两段交代场景、冲突或结论，不铺陈宏大背景。
- 正文每段只承担一个任务；优先使用具体名词和动词。
- 清单和步骤必须说明适用条件，不能只有口号。
- 结尾互动问题要具体到读者能回答，避免“你怎么看”。
- 标签服务于主题识别，不堆砌相近词或无关热词。

## 4. 卡片阅读弧线

推荐但不强制的页面角色：

1. 封面：单一承诺；
2. 场景/问题：让目标读者确认“与我有关”；
3. 结论预告：先给判断或框架；
4. 方法/解释：逐步交付；
5. 证据/案例：支撑关键判断；
6. 避坑/边界：说明何时不适用；
7. 总结/行动：压缩为可保存信息；
8. CTA：仅在确有必要时加入。

每页只能有一个主 takeaway。相邻页面必须形成推进关系，而非换句话重复。

## 5. 视觉与生图分工

- `html_css`：标题卡、流程、步骤、表格、数字、对比和信息图。
- `authorized_asset`：真实产品、截图、案例或品牌资产，必须有授权 ID。
- `generated_raster`：氛围场景、概念隐喻、人物活动、背景和装饰主体。
- `no_visual_needed`：文字已经完整表达且图像没有新增功能。

生成式图片应留出可预测的文字安全区。中文、数字、产品界面和数据图全部由 Renderer 叠加或绘制，图片模型只生成底图/主体。

## 6. ImageSpec 写法

每条提示词按以下顺序组合：用途与页面目标 → 场景 → 主体及动作 → 风格媒介 → 构图 → 光线 → 色板与材质 → 文字安全区 → 品牌约束 → 禁止项。

不要写“高级感、科技感、爆款”等不可执行形容词；改写成可观察的色彩、材质、镜头、光线、留白和构图。若 DesignDNA 没有指定风格，返回审核项，不擅自套模板。

## 7. 失败条件

- 封面承诺在后续页面未兑现；
- 页面无法回指事实或解释 ID；
- 图片 Prompt 要求模型绘制中文或产品界面；
- 卡片与发布正文互相矛盾；
- 每页都有生图需求但没有解释图像功能；
- 视觉风格覆盖或偏离 DesignDNA。

## 8. 八类内容目的在小红书的表达

| 内容目的 | 结构重点 | 适合的主要互动 |
|---|---|---|
| 热点/行业解读 | 事件 → 与读者的关系 → 影响清单 → 边界 | 转发或关注 |
| 知识干货分享 | 场景 → 步骤/清单 → 示例 → 避坑 → 总结 | 收藏 |
| 专业观点表达 | 争议/反差 → 判断 → 依据 → 反例 → 立场 | 评论或转发 |
| 产品/服务推广 | 问题场景 → 方案 → 适用对象 → 证据 → 边界 | 咨询、试用或购买 |
| 案例/成果展示 | 背景 → 挑战 → 过程 → 结果 → 可迁移经验 | 关注或咨询 |
| 品牌形象宣传 | 人物/场景 → 品牌故事 → 行动与价值观 | 关注或分享 |
| 互动话题讨论 | 共鸣/争议 → 选项或问题 → 参与提示 | 评论 |
| 活动/信息发布 | 核心亮点 → 对象 → 时间地点 → 参与方式 | 报名或转发 |

表格只用于模型选择最自然的一个动作，不是固定映射。内容本身更适合其他动作时可以调整，但必须给出理由。

## 9. 账号类型、创意机制与矩阵协同

- 公司官方号以组织能力、流程、证据和稳定交付建立信任，避免伪装成个人体验。
- 创始人或专家号以判断、经验边界和决策过程建立信任，不能虚构亲历与客户反馈。
- 员工号以具体岗位视角和真实工作场景建立信任，表达范围服从公司公开边界。
- 个人号以个人经历、能力和审美建立信任；没有第一手证据时不得使用“亲测”。

内容目的回答“为什么发”，创意机制回答“怎样让人愿意点开、看完并记住”。清单、对比、案例复盘、实验、观点冲突、热点桥接等机制应服务于同一内容承诺，不能为了模仿爆款改变事实或账号身份。

同一公司矩阵围绕同一主题发文时，每个账号至少在对象、场景、立场、证据、表达机制或 CTA 中形成两项差异；禁止复制同标题、同封面承诺和同正文，只做语气替换。

发布后优先记录曝光、封面点击、读完/滑完、收藏、评论、主页访问和咨询等分层信号。一次内容只冻结一个主要传播假设，便于反馈系统判断是选题、包装、内容还是承接环节需要调整。
