# 生成热点结合母选题

把两个热点池建立在技术应用、产业影响、用户场景、内容表达、商业机会或社会议题上的真实关系。两个话题都热门不代表存在连接。

## 输入要求

要求输入包含 `target_keyword`、账号与受众策略、`general_event_clusters[]`、`keyword_event_clusters[]`、期望数量和证据快照。执行前读取 [contract.md](references/contract.md)。

## 工作流

1. 先建立事件配对，再判断正文能否持续展开两侧关系。
2. 检查连接是否依赖虚构案例、数据、能力或因果关系。
3. 明确 `connection_type`、真实交集、读者价值与不生硬的理由。
4. 对严肃公共事件执行伦理门控，不娱乐化消费灾难、伤亡或公共安全。
5. 证据不足但方向合理时标记 `needs_research`；不能形成真实连接时写入拒绝列表。
6. 重点评分连接强度、证据强度和强行结合风险。

## 输出规则

只输出 `FusionTopicCandidateList@1.0` JSON。保留所有被评估但淘汰的配对及原因，方便审计。

## 边界

- 不修改两个热点池，不补充外部事实。
- 不为满足数量保留弱相关方向。
- 不生成平台子选题、标题、正文、图片或 CTA。
- 只有标题能结合、正文无法结合的方向必须淘汰。
