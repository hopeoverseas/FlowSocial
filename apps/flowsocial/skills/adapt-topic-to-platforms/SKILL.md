# 生成双平台子选题

保持母选题的事实、核心问题和证据边界不变，为两个平台重新设计读者任务。不得只替换语气或标题词。

## 输入要求

要求输入包含已审核母选题、账号策略、目标平台、Evidence 聚焦项、禁写项和平台阈值。执行前完整读取 [contract.md](references/contract.md) 与 [platform-rules.md](references/platform-rules.md)。

## 工作流

1. 提取母选题的事实骨架、核心问题、目标读者、可兑现收益、证据强弱和不可扩写项。
2. 先判断母选题对每个平台是否成立，再做改编；不得为凑齐双平台结果而强行生成。
3. 为小红书确定一个具体使用场景和一个单一承诺，设计收藏理由、评论问题、卡片拆页逻辑、封面信息与视觉叙事。
4. 为公众号确定一个中心论点和信息增量，设计开篇问题、论证链、边界讨论和转发理由。
5. 分别给出标题方向、证据聚焦、适配风险和 `fit_score`，并解释评分依据。
6. 检查两个平台是否仍共享同一事实骨架，同时在阅读任务、内容结构和用户收益上有实质差异。

## 强制门控

- 小红书缺少具体场景、可收藏信息或可拆页结构时标记 `needs_review`。
- 公众号缺少足够证据支撑连续论证时标记 `needs_review`。
- 没有经历证据时禁止建议“亲测、我用了、亲身经历”等第一人称角度。
- 不用“震惊、必看、全网都在”等空洞热词代替选题价值。
- 平台适配分低于调用方阈值时填写 `not_suitable_reason`，不强行进入写作。

## 输出规则

只输出 `PlatformTopicPair@2.0` JSON，不附加解释性正文。

## 边界

- 不修改母选题、Evidence、核心事实和禁写项。
- 不生成完整标题、正文、文章大纲、卡片成稿或图片 Prompt。
- 不联网，不新增产品、案例、数据和个人经历。
