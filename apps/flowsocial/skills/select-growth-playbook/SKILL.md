# 选择账号组合与增长打法

## 输入

读取 `StrategyInputBundle@1.0`、当前公司的社媒账号清单，以及编排器提供的候选方法卡。候选卡是唯一允许选择的打法；完整读取 [references/contract.md](references/contract.md) 和 [references/playbook-policy.md](references/playbook-policy.md)。

## 工作流

1. 区分公司共享事实、矩阵决策和单账号决策。
2. 判断当前是否真的需要矩阵。只有多个账号能形成独立身份、受众、内容或承接分工，并且团队有能力维护时，才推荐 `role_matrix`。
3. 为每个账号确认平台、对外身份、信任来源、阶段和矩阵角色；缺失项保留为未决，不得猜成事实。
4. 只从候选方法卡中选择最多三个适用方案进行比较，说明适用条件、风险、观察窗口和退出条件。
5. 推荐一个当前方案。用户明确选择的增长模式优先；高风险热点实验必须保留风险和退出条件。
6. 热点分为 `direct / bridge / weak_experiment / unrelated`。默认禁止完全无关热点，禁止自动删除历史内容。
7. 内容比例只能作为实验目标区间，不得写成平台算法规律或成功承诺。
8. 输出账号组合和增长打法建议，等待用户在完整策略草案中确认。
9. `single_account` 只能把 `primarySocialAccountId` 纳入活动策略与内容计划；其他账号保留为待规划，不得生成活动任务。
10. `role_matrix` 必须为每个入选账号给出不同的矩阵角色、内容职能目标、推荐节奏与转化责任，不能复制同一份账号策略。
11. 小红书与公众号分别比较平台适配打法。每个账号至少提供一个推荐打法和一个备选打法，并说明平台机制、推荐理由、资源要求、观察窗口与退出条件。
12. 所有进入执行层的选择必须携带账号、打法版本和实验标识，供 ContentRun 追溯。

## 边界

- 不创建或删除社媒账号。
- 不生成具体选题、标题、正文、图片或发布日期。
- 不推荐刷量、虚假互动、伪装素人、批量重复发布或规避平台治理。
- 不把单个经验样本写成平台确定性规则。
- 不自动激活策略，不修改事实库和方法库。
- 兼容没有账号组合扩展的历史单账号策略；兼容模式不得反向改写历史快照。

只输出 `GrowthPlaybookSelection@1.0` JSON。
