# 公众号文章生成规则

## 1. 阅读与转发任务

公众号文章不是加长版卡片。它要让读者在连续阅读中获得比热点摘要更多的解释、判断或行动框架，并能清楚说明为什么值得转发给特定的人。

文章至少完成以下一项：

- 解释事件背后的原因或机制；
- 评估事件对目标读者的影响；
- 将分散信息整理成决策框架；
- 用证据支持一个有边界的观点；
- 把案例转化为可迁移的方法。

## 2. 标题与摘要

- 标题明确主题和信息增量，可使用问题、结论、反差或方法，但不隐瞒关键前提。
- 标题的确定性不得高于证据；不写无法证明的“彻底、必然、所有人”。
- 摘要用 2–4 句交代发生了什么、文章解决什么问题以及读者能获得什么。
- 标题和摘要不可依赖“真相竟然是……”式悬念维持点击。

## 3. 开篇

开篇尽快建立相关性，可从事件、具体场景、核心问题或结论进入。避免长篇时代背景、虚构故事、万能金句和与中心论点无关的情绪铺垫。

## 4. 论证结构

每一节明确承担以下一种功能：定义问题、补充背景、解释原因/机制、提供证据、讨论影响、给出反例/边界、形成结论或行动建议。

相邻章节需要推进关系。若删除一节不影响文章逻辑，检查它是否为冗余。观点必须标为观点，解释必须有事实基础，未知项不得被写成确定结论。

## 5. 公众号表达

- 保持完整句和自然段落，不把每句话都拆成单独一行。
- 小标题帮助导航而非制造数量感；层级一般不超过三级。
- 使用必要的例子、类比和过渡，但不虚构对话或经历。
- 结论回到目标读者的判断或行动，不空泛升华。
- CTA 与文章价值相关，且营销/合作关系按输入要求披露。

## 6. 发布前检查

- 动态事实是否需要在发布当天复核；
- 标题、摘要、正文和结论是否兑现同一承诺；
- 每个数字、引语、案例和产品能力是否可追溯；
- 是否遗漏反例、适用条件或重要不确定性；
- 转发摘要是否准确代表全文，而非二次夸大。

## 7. 八类内容目的在公众号的表达

| 内容目的 | 文章重点 | 适合的主要互动 |
|---|---|---|
| 热点/行业解读 | 背景、机制、影响、判断和边界 | 转发或关注 |
| 知识干货分享 | 问题、完整方法、步骤、示例和适用条件 | 收藏式留存或转发 |
| 专业观点表达 | 核心判断、依据、反方观点和结论 | 评论或转发 |
| 产品/服务推广 | 需求、方案逻辑、适用对象、证据和边界 | 咨询、试用或购买 |
| 案例/成果展示 | 背景、挑战、方案、过程、结果和复盘 | 咨询或关注 |
| 品牌形象宣传 | 组织故事、人物、行动、理念和业务联系 | 关注或转发 |
| 互动话题讨论 | 议题背景、多方观点和明确问题 | 评论或参与调研 |
| 活动/信息发布 | 发布背景、核心信息、对象、议程和参与方式 | 报名或转发 |

主要互动方式由文章内容决定，表格仅作为默认倾向。不要为了覆盖所有指标在结尾罗列多个动作。

## 8. 账号类型与信任来源

- 公司官方号依靠组织事实、专业流程、案例证据与持续交付建立信任。
- 创始人号依靠经营判断、取舍过程和第一责任人视角建立信任。
- 专家号依靠解释能力、方法边界和可复用框架建立信任。
- 个人号依靠真实经历、稳定观点与人格一致性建立信任。

文章口吻、第一人称和证据来源必须与账号身份一致。公司号不伪装个人亲历，个人号也不能替公司作出未经授权的承诺。

## 9. 公众号的关系承接

公众号内容既是单篇文章，也是长期内容资产。生成时应在调用方提供的真实基础设施范围内设计：

- 文章属于哪个稳定栏目，能否沉淀为系列；
- 读者为何值得关注下一篇，而不是只完成一次阅读；
- 可关联哪些历史文章、菜单入口或关键词回复；
- 从订阅、搜索、平台推荐和社交转发四个发现入口看，标题、摘要与分享语分别承担什么任务；
- 当前旅程阶段适合关注、阅读下一篇、领取资料、咨询还是报名，只选择一个主要下一步。

不存在的栏目、菜单、关键词回复、资料包和历史文章不得虚构，应返回空值或审核提醒。

## 10. 创意机制与矩阵协同

内容目的回答“为什么发”，创意机制回答“怎样组织论证并促进传播”。框架、案例复盘、行业分析、观点、热点桥接和故事等机制只能改变表达路径，不能改变事实、推广边界和中心论点。

同一公司矩阵围绕同一主题发文时，应按账号角色区分判断角度、证据层级、读者对象和承接路径。禁止把同一篇文章简单改标题后投放到多个账号。
