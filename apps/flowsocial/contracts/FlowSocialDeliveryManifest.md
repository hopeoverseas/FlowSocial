# FlowSocialDeliveryManifest@3.0

离线包准备清单，不是生产发布或用户选择证明。严格字段为 `schemaVersion=3.0`、contract/id/source、legacy ref、任务版本、snapshot ref、逐页 revision/source/source SHA-256/normalized SHA-256/Gate 摘要、独立 package/download/platform delivery/user selection 状态、event refs、时间、blockers 与 `manifestHash`。

Manifest 2.0 仅由只读 Adapter 投影；缺页或缺资产 hash 返回明确 blocker，所有质量和交付状态保持 `legacy_unknown`，不覆盖历史对象。3.0 的原始选择页必须由候选、修订和 hash 完全一致且未被 rejected 的 `candidate_selected` 证明；恢复页不得伪造新选择事件，只接受完整绑定 current/source/previous revision 的 `page_restored`。恢复 revision 除恢复操作允许变化的标识、父子关系、操作、source ref、操作者、时间与对象 hash 外，其余不可变业务内容必须与 source revision 完全一致。整套恢复还必须绑定 current/source/previous snapshot、逐页恢复修订以及先逐页后整套的连续事件链，并保持每页除新 revisionRef 外的 source 与 gateSummary 等于 source snapshot 对应页。空事件、缺页、链断裂、内容偷换、引用错误或恢复后拒绝均 blocked。逐页源/规范化 hash 均绑定实际证据；任意字段改变使完整对象 hash 失败。05F 离线事件禁止写 `platformDeliveryStatus=delivered`，真实 delivered 仅由 activeBatch 解锁后的 05H 生产 Adapter 写入。关闭 Offline Delivery Flag 阻止包准备，回退保留 2.0 只读路径与既有交付流程。

05L 不改变 Manifest 3.0 schema 或字段语义。`integrated_page_generation` 页只允许把已选择 revision 绑定的规范化 1080×1440 PNG 原字节复制到隔离交付目录，交付 SHA-256 必须等于 revision asset SHA-256，且不得创建 HTML、调用 HTML Renderer 或二次叠字。`deterministic_layout` 页继续显式委托既有 Renderer，Renderer 输出允许与 revision 输入不同，但必须重新通过 1080×1440 和 Renderer 质量证据 Gate。Manifest `sourceSha256` 始终保持 normalization input/source hash 的既有含义；integrated 页 `normalizedSha256` 继续绑定规范化直通 PNG；deterministic 最终 Renderer PNG 不写入或覆盖 Manifest 现有 hash 字段，只记录在伴随 Evidence 1.0。混合快照逐页保留 `normalized_integrated` / `deterministic_layout` 来源，禁止静默切换。

隔离目录同时写入兼容证据 `XhsIntegratedPageDirectDeliveryEvidence@1.0`：`schemaVersion/contract/requestHash/snapshotRef/pages/createdAt/evidenceHash`。逐页证据冻结 `pageId/source/generationMode/revisionRef/relativePath/bytes/sha256/dimensions/revisionAssetSha256/manifestSourceSha256/byteIdentity/rendererInvoked/qualityEvidenceHash`；其中 `manifestSourceSha256` 必须等于 Manifest 原 `sourceSha256`，`sha256` 才表示最终交付 PNG。`evidenceHash` 进入 Manifest ID，Manifest hash 再由不可变 `package_prepared` 事件引用，因此 deterministic 最终输出 bytes/hash、尺寸、来源和 Renderer 质量摘要形成独立可验证链，同时不改变 Manifest 字段语义。它是 Manifest 3.0 的伴随兼容证据，不改写历史 Manifest、revision 或 snapshot，也不要求迁移旧包。

直通提交采用可恢复两阶段：先在同一隔离父目录完成全部 PNG、Manifest 和证据的 stage 写入与复核，再原子 rename 为最终目录，最后追加 `package_prepared` 事件。写入或 rename 失败只清理 stage；事件提交前失败清理最终目录；事件已提交但调用方收到异常时按事件与目录重新核对后返回成功。若进程在 rename 后、事件前中断，同一请求可从目录证据恢复并只追加一次事件。幂等键在目录冲突和任何新写入前按 snapshot、canonical delivery root、actor 和 key 解析；同请求重放不写文件、不调用 Renderer、不推进 store version，不同请求复用 key 硬阻断。delivery root 与 offline store root 必须经 canonical/realpath 判定双向不重叠；关闭 `XHS_INTEGRATED_PAGE_DIRECT_DELIVERY` 仅阻止创建新直通包，历史 Manifest、revision、snapshot 和恢复事件保持只读可用。
